# LINUX RUNTIME dependency lock -- what the Docker image actually installs.
#
# `backend/requirements.lock.txt` was resolved on Windows (see its own header)
# and explicitly documents that "the authoritative lock for deployment should
# be regenerated inside the Linux container at freeze time." This file is that
# regeneration, produced with the exact command it prescribes:
#
#     docker run --rm -v "$PWD:/w" -w /w python:3.14-slim sh -c \
#       "pip install -q -r backend/requirements.txt && pip freeze" \
#       > backend/requirements.docker.lock.txt
#
# The Dockerfile installs from this file, not from requirements.lock.txt --
# `pip install --no-deps -r backend/requirements.docker.lock.txt`.
#
# WHY A SEPARATE FILE, NOT AN OVERWRITE. requirements.lock.txt is what local
# Windows dev environments and CI on Windows install from; overwriting it here
# would silently drop `colorama` (Windows-only, harmless to lose on Linux, not
# harmless to lose on Windows) for every contributor who has never touched
# Docker. Two lock files, one per platform that actually runs the app, mirrors
# the existing requirements.lock.txt / requirements-dev.lock.txt split.
#
# DIFFERENCES FROM requirements.lock.txt (both are correct for their platform):
#   - colorama is absent: it carries `; sys_platform == "win32"` and never
#     installs on Linux.
#   - uvloop==0.22.1 is present: a POSIX-only high-performance event loop that
#     uvicorn's standard extras pull in only on Linux/macOS.
#   - reportlab==5.0.1 vs 5.0.0: an independent resolution difference between
#     the two freeze runs, not a platform marker -- both are valid pins.
#
# VERIFIED. Installs cleanly with `pip install --no-deps` in python:3.14-slim
# (2026-08-21). Not yet re-run against the full test suite inside the
# container -- do that before treating this as equally proven as the Windows
# lock's "214 tests pass" claim.
#
# TO CHANGE A VERSION: edit backend/requirements.txt, re-resolve on Windows
# into requirements.lock.txt as usual, then regenerate this file with the
# command above. Never hand-edit a pin here.
