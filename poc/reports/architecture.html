02 — Shape

Architecture

Seven layers, numbered because they are a genuine dependency order — each was built and tested before the one above it existed, and each depends only on what is below.

1

Constraint layer

Disposition thresholds, one-directional correction, system invariants, the agent capability matrix and the hash-chained audit trail. Written first and proven correct before anything autonomous was pointed at it.

policy.py · gate.py · audit.py · config.py · market_data.py
2

Synthetic book

12 loans, 161 documents, 19 planted defects, one deliberately clean file. Deterministic on a fixed seed. Ground truth is recorded separately and never enters the system.

generate_synthetic_data.py · verify_synthetic_data.py
3

Persistence & rules

The schema, the single guarded write path, and eleven deterministic rules that recompute quantities rather than reading them. This is the layer that can contradict the model.

models.py · db.py · store.py · rules.py · seed.py
4

Tool layer

Thirteen handlers behind one dispatcher. Budget, gate, schema validation, execution and recording happen in that order, for every tool, with no faster path available to anything.

tools/runtime.py · tools/handlers.py · guidelines.py · documents.py
5

Agents

Four system prompts and one loop that runs any of them. Every model-initiated tool call goes through the same dispatcher as a scripted one.

agents/prompts.py · agents/runner.py · agents/__init__.py
6

Interface

Human capability matrix, the actions people take, read models, the HTTP API, and a six-screen React app. Every mutating endpoint re-checks the role before it writes.

rbac.py · human.py · reporting.py · api.py · frontend/
7

Evaluation

Scores what the agents found against what was planted. Five verdicts, not two. Found three bugs in the data it was scoring against on its first full run.

evaluation.py · evaluate.py

05 — Capability

Tools

Thirteen, each with a posture that drives gating, logging and colour. Which agent may call which is a matrix in Python, not a line in a prompt.

toolposture intakevalidationprocessingsummarizer does

Separation of duties between agents, for the same reason it exists between people. Validation may raise a finding but never repair one. Processing may repair but never raise. The Summarizer holds read-only tools and nothing else. This is also why a prompt-injected document is ineffective: persuading an agent to call a tool it does not hold changes nothing.

What the dispatcher does, for every call

step 1

Count the budget

Counted before the call runs, so an over-budget run cannot squeeze in one more expensive tool on the way out.

step 2

Check the gate

Capability, run-open, loan scope, and for gated tools an argument-bound human confirmation.

step 3

Validate arguments

Against the declared schema. The API enforces strict tools too, but tests and HITL endpoints have no server in front of them.

step 4

Run the handler

A handler that throws becomes an error result, not a dead run.

step 5

Record the attempt

Permitted or refused, with arguments redacted. A run full of denials is a signal, and only if it is written down.

exception

Refusals return

A denial comes back as is_error with a plain-English reason so the model adapts. Only budget exhaustion propagates and ends the run.

06 — Actors

Agents

Four, run in a fixed order that is a data dependency rather than a preference. Each gets its own run id, its own budget and its own line in the audit trail.

The prompts are not the safety layer. Everything that matters — which tools an agent holds, whether a finding is auto-repaired, whether a repair is permitted — is enforced in Python. The prompts exist to make an agent effective inside those limits and to explain them, so it does not waste turns discovering them.

07 — Loop

Orchestration

A hand-written loop, not the SDK tool runner. The spike concluded otherwise; that was reversed once the tool layer existed.

why manual

Three reasons the runner did not fit

It builds schemas from function signatures (we have thirteen hand-written strict ones with tests); it cannot mark a result is_error, which is the shape of every gate refusal; and it owns the loop, so a budget ceiling is discovered a turn late.

request

Two stable system blocks

Agent prompt, then the program’s guideline pack with the cache breakpoint at its end. Nothing loan-specific goes above that line — one loan id there would silently stop the cache ever hitting.

turn

Batched tool results

All results from one assistant turn return in a single user message. Splitting them trains the model out of parallel calls for the rest of the run.

thinking

Adaptive, explicitly

thinking: adaptive with effort: high. Omitting the parameter on Opus 4.7 means no thinking at all, so it is always set. Thinking blocks are echoed back unchanged.

budget

Four ceilings per run

Tool calls, tokens, seconds and dollars. Spend is written to the run row every turn, so a run that dies expensively still records what it cost.

handoff

Approval crosses runs

A gated call is refused and queued. A supervisor authorises. The next run loads approved tokens into its context and the identical call passes. A person authorises; an agent acts.

08 — Arithmetic

Rules engine

Eleven pure functions over a Facts snapshot. No database, no model, no raising. They recompute quantities rather than reading them, which is what lets them contradict the model.

Three outcomes, not two. A rule with a missing input returns INDETERMINATE and names what is missing — never PASS. If dti_within_program passed when income had never been extracted, a file with no income documentation would clear the capacity check. Two further guards were added after a real run: a value containing an illegibility marker is not a number, and an extraction below 0.60 confidence is withheld from the engine entirely, with the rule reporting the confidence rather than pretending the field was absent.

09 — Judgment

Disposition policy

The model supplies an observation, a severity and a confidence. Python decides what follows. The finding schema has no lane parameter, so a model emitting one has nowhere to put it.

auto thresholds

Per type, never one number

missing_document 88 · expired_document 88 · low_confidence_ocr 85 · flood_determination_mismatch 90 · flood_cert_missing 90 · fee_tolerance_variance 92

“88% sure a document is missing” and “88% sure this income is right” are not the same claim.

never automatic

Ten judgment calls

income_variance · dti_breach · ltv_breach · title_exception · identity_mismatch · appraisal_variance · undisclosed_debt · unsourced_deposit · aus_referral · prompt_injection

A machine may analyse them; a person decides.

supervisor sign-off

Five require a second pair of eyes

dti_breach · ltv_breach · title_exception · identity_mismatch · prompt_injection

An analyst may only propose; a supervisor closes it.

structural

Unknown types route to a human

An unrecognised type is compared against a sentinel of 101, which no confidence can reach — so it routes to a person structurally, not by luck.

correction

One-directional

Confidence may be revised down, never up. A finding may move auto → HITL, never back. Both raise rather than clamp — a silent clamp hides the bug that caused it.

readiness

Derived, never assigned

A loan is ready when every stage-0–2 finding is closed and at least one has moved. Re-derived after every write; a violation rolls the whole transaction back.

Memory cannot be poisoned by the model. A note is only written by a human resolution or a verified outcome, so an agent cannot assert something and later read its own assertion back as established fact. The guideline pack is authored and cached, ~2,400 tokens per program, byte-identical for every loan of that program — 816,000 tokens were served from cache across the last full evaluation, which is the largest single cost lever in the build.

11 — Controls

Security

Two capability matrices, one for agents and one for people, consulted in Python before any write. Everything else is defence in depth around them.

Human capability matrix

actionanalystsupervisorunderwriter
view_pipeline / view_exceptions / view_hub / view_audit

confirm_gated
start_scan
decide_loan

A supervisor cannot render an underwriting decision, and an underwriter cannot work a HITL case. Approving a fix and deciding a loan are different jobs; collapsing them would make the approval lane decorative.

Controls

agent capability

The tool refuses, not the interface

Every call passes gate.check(): capability, run-open, loan scope, and confirmation for gated tools. Refusals are returned to the model and recorded.

human capability

Hiding a button is not a control

The React app hides what a role cannot do because showing it is bad design. Every mutating endpoint re-checks rbac.require() regardless. Tests post with the wrong role on purpose.

tokens

The role comes from the roster

A token carries a username; the role is looked up server-side. A forged role: supervisor claim grants analyst access.

argument binding

Confirmation is not a blanket

A confirmation token is the tool name plus its exact arguments. Authorising an appraisal never authorises a title order, or the same order on a different loan.

audit

Tamper-evident, not just logged

Each row stores sha256(prev_hash + payload). Editing or deleting any historical row breaks every hash after it. UNIQUE(prev_hash) makes a fork impossible; the API re-walks and rehashes the whole chain on every request.

redaction

Before hashing, never after

Sensitive keys are stripped before a payload enters the chain — once a value is inside a hash it cannot be removed without breaking every row that follows.

injection: detect

Seven markers, in Python

Raw bytes scanned before any model sees them: override, system impersonation, role reassignment, forced disposition, suppressed findings, fake authority, hidden delimiters. A tripwire, not a filter — a PASS means “no known marker”, never “safe”.

injection: frame

The delimiter cannot be closed

Document text is wrapped and labelled untrusted, with an integrity banner the document cannot argue away. Any closing tag inside the body is escaped visibly, so the attempt stays in the transcript.

injection: contain

The only actual control

Assume detection and framing both failed and the model complied fully: Validation still holds no repair tool, and prompt_injection is never automatic. Tested both ways.

secrets

One code path, three mechanisms

Plain environment variables always. Local .env, Docker --env-file, Azure Key Vault reference resolved by managed identity. Never in the repo, an image layer, CI logs, or anything the bundle can reach.

integrity

Foreign keys are opt-in on SQLite

PRAGMA foreign_keys=ON per connection, so evidence cannot point at a document that does not exist. Invariants re-run inside the transaction; a violation rolls back the write and its audit line.

evidence

Quotes are verified

A quote that does not appear in the cited document lowers the finding’s confidence and routes it to a human. The observation survives; the confidence that auto-closed it does not.

What the scorer measures

recall

Did we find it at all

A mislabelled finding counts as detected — it reached a human, just the wrong queue.

type accuracy

Having found it, named right

Where a real finding ends up in the wrong queue. Currently 100%.

lane accuracy

Routed as the defect deserved

Auto versus human versus sign-off. Currently 100%.

precision

How much was real

Duplicates counted separately from invented findings — they are wasteful, not wrong, and the remedy differs.

calibration

Is a 95 better than a 65

Hit rate per confidence band. If the bands are flat, the number the auto threshold routes on carries no information.

isolation

Ground truth never enters

Read from disk by the scorer alone — never seeded, never in a prompt. The verify script asserts it has not leaked into any document.

14 — Honest

What is not built

Known, scoped, and deliberately deferred.

  • No Dockerfile or deployment. Held until the feature set settles after team testing.
  • Recall is 68.4% — 13 of 19 planted defects. All six misses are in areas with no rule: AUS results, document expiry, title exceptions, credit inquiries. Where a rule points at a document the agents find the defect; where none does, they do not look. Four rules is the lever.
  • Nobody has visually reviewed the UI. It was built without a browser available. Typechecks and unit tests pass; layout has never been seen.
  • Demo-grade auth. Five accounts share one password, and the SSE endpoint takes its token in the query string. Fine on localhost, nowhere else.
  • No Entra ID. AnthropicFoundry accepts azure_ad_token_provider, which would remove the API key entirely — strictly better than a key in Key Vault, since there is no long-lived secret to rotate. Noted for deployment.
  • Calibration is under-measured. The 90–100 band is 12/12, but the middle bands are empty and n is small. No conclusion should be drawn from 13 findings.
  • Single SQLite file. WAL is on and it is fine for a demo; concurrent writers beyond one process are not a tested path.
